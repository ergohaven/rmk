## Ergohaven RMK Firmware v0.3.0

Firmware for K:03, K:04, K:04 Mini, K:04 Micro, Imperial44, OP36 and Velvet in Standalone and Qube configurations, plus the new wired Phenom, Phenom Mini and Phenom Micro. Default images use RMK/Rynk. Separate RMK/Vial standalone images are available for K:03, K:04 Micro, Imperial44, OP36 and Velvet.

**Upgrade warning:** export your layout before flashing. Upgrading from v0.2.0 changes the storage schema and clears settings and pairing on every part. Update Entropy first, flash every matching part, import your layout and pair again. See the compatibility notes below before selecting an archive.

### Features

- Added the Phenom Series: wired RP2040 split firmware with the K:04 module stack, Universal Symbols, Layout Sync and per-half layer LEDs. Configure each module in Entropy; Phenom starts with both module slots set to `None` ([#45](https://github.com/ergohaven/rmk/pull/45)).
- Added Ergohaven commands over Rynk for board definitions, layout options, QSID settings, half batteries, host data and staged writes with explicit commit/status reporting. Rynk images provide a 4096-byte macro pool and 4128-byte frames; Vial images retain a 2048-byte pool ([#45](https://github.com/ergohaven/rmk/pull/45)).
- Added independent Qube display brightness, black/blue backgrounds and compact/large text, with black/large defaults. Media fields carry up to 64 UTF-8 bytes and long titles scroll ([#45](https://github.com/ergohaven/rmk/pull/45), [#63](https://github.com/ergohaven/rmk/pull/63)).
- Added persistent Sticky Mode toggle/on/off keys for K:04, Phenom and Velvet, with per-side controls where supported; existing assignments retain their numeric slots ([#77](https://github.com/ergohaven/rmk/pull/77)).
- Added persistent Universal Symbols PC/macOS mode, the `№` symbol and model-specific ANSI/ISO geometry support. Separate Vial profiles cover the approved standalone models; Rynk K:04 and Micro gain the matching geometry support. Mini and Qube retain their established geometry ([#51](https://github.com/ergohaven/rmk/pull/51), [#73](https://github.com/ergohaven/rmk/pull/73), [#74](https://github.com/ergohaven/rmk/pull/74)).
- Added Universal language controls, symbols and Russian letters to extended Vial macros, preserving uploaded native actions and firmware layout state when a switch cannot be emitted at full keyboard-report capacity ([#61](https://github.com/ergohaven/rmk/pull/61), [#69](https://github.com/ergohaven/rmk/pull/69)).
- Made standalone K:04-family Bluetooth profiles discoverable as model-specific BT0–BT4 names without changing their addresses or USB/split identities ([#70](https://github.com/ergohaven/rmk/pull/70)).

### Improvements

- Integrated upstream RMK through [`a0ccc40f`](https://github.com/ergohaven/rmk/commit/a0ccc40f0933366b5a076562104071f1e3281bb0), including the new host, storage, split and macro architecture. Ergohaven firmware versions remain independent of upstream Cargo crate versions ([#45](https://github.com/ergohaven/rmk/pull/45), [#56](https://github.com/ergohaven/rmk/pull/56), [#68](https://github.com/ergohaven/rmk/pull/68)).
- Improved K:04 Qube trackball scheduling with 3 ms connection events spaced 3.75 ms apart. K:04, Mini and Micro through Qube connect to the computer over USB only; BLE remains active between Qube and the halves ([#47](https://github.com/ergohaven/rmk/pull/47)).
- Coalesced board-setting and macro writes after the host becomes quiet and bounded flash-operation waits. Updated the Nordic backend to include its flash-lock correction; the temporary vendored override is no longer the active solution ([#49](https://github.com/ergohaven/rmk/pull/49), [#50](https://github.com/ergohaven/rmk/pull/50), [#56](https://github.com/ergohaven/rmk/pull/56)).
- Expanded the official matrix to 22 profile archives and 51 keyboard UF2 roles: 15 standalone pairs, including the five Vial variants and three Phenom models, plus seven Qube triples. The separate full-size K:04 Vial production artifact is retired; K:04 Rynk and Qube remain supported.
- Updated CI coverage planning, verified same-source coverage reuse, grouped example builds and host/Wasm checks. These infrastructure changes are not a claim of new hardware validation ([#43](https://github.com/ergohaven/rmk/pull/43), [#44](https://github.com/ergohaven/rmk/pull/44), [#57](https://github.com/ergohaven/rmk/pull/57), [#59](https://github.com/ergohaven/rmk/pull/59), [#68](https://github.com/ergohaven/rmk/pull/68)).

### Fixes

- Preserved usable host-selected standalone K:04 BLE connection intervals instead of repeatedly disconnecting when a preferred interval is refused ([#42](https://github.com/ergohaven/rmk/pull/42)).
- Separated known BLE security identities from selected-profile admission, reconciled keys after releasing the previous session, and reset stale GATT subscriptions before restoring the selected profile. Known inactive hosts can no longer enter an empty slot as a new pairing peer ([source](https://github.com/ergohaven/rmk/commit/288e919e014de6d3614f642aa8011bd0f168c588)).
- Restored the legacy K:04-family LED policy for standalone and Qube halves: one-second profile/battery overlays, cyan pairing, white reconnect, yellow split search, green connection, yellow/green USB indication at 95%, non-base-layer precedence and USB-aware sleep. The intermediate cyan USB-only policy from #67 is superseded, not the final release behavior. USB indication uses the available cached battery level; this is not a measurement of charging current or termination, and sleeping cable detection still depends on the existing wake/event path ([source](https://github.com/ergohaven/rmk/commit/e8ffaf8544486ec6b3d7910bbccd4384e325f140)).
- Preserved mouse-layer ownership during modifier-assisted clicks, held-button drags and touchpad holds while either pointing device moves. Unbound non-mouse keypresses now participate in auto-layer deactivation ([#53](https://github.com/ergohaven/rmk/pull/53), [#54](https://github.com/ergohaven/rmk/pull/54), [#58](https://github.com/ergohaven/rmk/pull/58), [#62](https://github.com/ergohaven/rmk/pull/62)).
- Restored cadence-aware K:04 trackball acceleration and local Velvet pointing activity so motion requests active host-link parameters after idle ([#55](https://github.com/ergohaven/rmk/pull/55), [#64](https://github.com/ergohaven/rmk/pull/64)).
- Preserved modifier/letter press and release order for shortcuts, and placed the keyboard collection before Vial in the BLE HID report map for macOS Caps Lock input-source switching ([#52](https://github.com/ergohaven/rmk/pull/52), [#65](https://github.com/ergohaven/rmk/pull/65)).
- Made a nonzero Fast typing window enable default Flow Tap while zero disables it, retaining explicit per-key overrides. This also changes the effect of replaying an older backup containing a nonzero QSID 27 ([#66](https://github.com/ergohaven/rmk/pull/66)).
- Restored state, module settings and active-layer synchronization when a wired peripheral reboots independently; corrected Phenom encoder direction, left-touchpad default rotation and right-trackball delivery. Kept failed battery samples from replacing the last known level and refreshed Qube half-battery caches ([#45](https://github.com/ergohaven/rmk/pull/45)).
- Retained split peer filtering and sleeping reconnection, prevented recursively triggered macros, split oversized mouse deltas into representable reports, and prevented Rynk request/topic deadlocks ([#45](https://github.com/ergohaven/rmk/pull/45)).

### Compatibility and flashing

1. **Back up before updating.** Export in your current Entropy, then update to an Entropy build supporting Rynk and Ergohaven wire revision 2 for the default images. The storage-format/feature transition from v0.2.0 clears keymaps, macros, combos, forks, Morse entries, module settings, host bonds and split pairing on all parts. The product version bump alone is not an upstream crate/schema bump.
2. **Choose the protocol explicitly.** Only archives with `-vial-` are the five separate Vial variants. Full-size K:04 Vial is not an official production download. Vial native-action protocol revision 2 needs a compatible configurator; do not assume an older Vial client understands Ergohaven extensions. Vial definitions still advertise the existing model-only updater asset names, not protocol-specific routing; select a matching archive manually. Phenom currently has no embedded updater asset selector.
3. **Flash complete matching sets.** Standalone uses both half images from one archive; Qube uses its dongle and both halves from one archive. The split wire format changed, so do not mix old/new parts, models, topologies or protocol variants. Velvet standalone has the **right main/central and left peripheral**. Phenom is RP2040, not nRF52840. Re-pair hosts and halves after the upgrade, then import your backup. Default Rynk images change the USB/BLE serial prefix from `vial:f64c2b3c:` to `rynk:` while keeping the underlying device ID; discovery may therefore treat them as a different interface. If a host retains an old BLE HID report map, forget that pairing and pair again.
4. **Review settings after import.** Restoring nonzero Fast typing window/QSID 27 enables default Flow Tap for inheriting keys; explicit per-key settings remain authoritative. K:04 standalone and Qube auto-layer timeout tables differ, so QSID 324 does not transfer equivalently between topologies. Phenom does not import QMK firmware settings and needs its modules selected in Entropy.
5. **Back up before downgrading too.** Qube display settings use the newer v6 board-settings record. Older firmware can reset module settings and misread layer names. Changing protocol/features can also reset the main storage schema. Do not run the legacy storage migration utility for this upgrade or on K:04 Series. Reset/migration/hardreset utilities are not included in normal release archives.
